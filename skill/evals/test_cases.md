# 拉条子改写评测用例

每个用例包含：**输入（粗糙中文原文）→ 期望输出特征（结构化校验点，非逐字答案）**。

模型自查时应能用这些校验点逐条比对自己的输出。

---

## 用例 1：信息充分的数据汇报

### 输入
> 4 月 GMV 1.5 亿，环比 +12%。订单 95 万，环比 +6%。客单价 158 元，环比 +5.7%。新客 8 万，次留 23%。库存周转 28 天，比上月慢了 3 天。下月计划重点是周转。

### 期望输出特征
- 总论点 1 条，覆盖"经营态势 + 周转隐忧"
- 一级论点 3–5 条，覆盖"经营结果 / 经营动作 / 隐忧 / 后续动作"或等价范式
- 二级短判断全部无标点，长度 8–18 字
- 数据全部来自原文（1.5 亿 / +12% / 95 万 / +6% / 158 / +5.7% / 8 万 / 23% / 28 天 / +3 天）
- 不出现 `GMV：` `订单：` 等字段名
- 库存周转作为隐忧而非顺手提及
- 下月动作落到"周转"具体抓手

## 用例 2：信息严重缺失的数据汇报

### 输入
> 这个月感觉还行，GMV 涨了一些，订单也涨了，新客投入做了不少。下月继续。

### 期望输出特征
- 模型**不得编造**"涨了一些"的具体数值
- 凡是原文未给数字处，必须出现 `待补充：XX数据` 占位符
- 仍能形成 3 条以上一级论点（用占位符填）
- 短判断仍合规：长度 8–18 字、无禁用标点、非字段名
- 不出现"我们觉得""大概""感觉"等口语
- 不输出"等待数据补充后再回汇"作为偷懒兜底——必须先成稿，再标占位

## 用例 3：SQL / 建表进度（执行语言占主导）

### 输入
> 这周建了订单宽表、用户标签表、和会员标签表，跑了一些 SQL 校验数据，还修了 GMV 重复计算的 bug。下周写文档。

### 期望输出特征
- 模型**必须**将"建表 / 跑 SQL / 修 bug"改写为业务价值语言
- 短判断不得为 `订单宽表：` `SQL：` `Bug：` 等字段名
- 业务价值表达示例：
  - "订单宽表上线支撑多维经营分析"
  - "GMV 重复计算缺陷修复数据可信度恢复"
- 数据缺失处统一占位
- 下周文档动作落到"降低跨团队取数沟通成本"等业务价值表述

## 用例 4：BI 看板上线 + 性能问题

### 输入
> 经营看板上线了，反馈打开慢，准备做缓存。

### 期望输出特征
- 即便信息极少，仍须形成"上线达成 / 反馈与风险 / 后续动作"三段
- 不出现 `看板：` `性能：` 字段名
- 性能反馈段必须含"反馈数 / 影响 / 初步根因 / 下一步"四要素（数据用占位符）
- 整体不超过 600 字

## 用例 5：项目复盘（成功 + 单点风险）

### 输入
> 双 11 数据保障没出大问题，看板正常，中间有一次延迟，是消息队列堆积。压测做了，SOP 启动了。下次提高压测频率，加细告警。

### 期望输出特征
- 总论点必须同时承载"整体达标 + 单点风险"
- 单点风险（消息队列）必须独立成一级或独立二级，不得被"整体达标"掩盖
- 后续动作必须落到"压测频率升级"与"告警颗粒度"两条具体抓手
- 短判断不得为 `延迟：` `压测：` `SOP：`

---

## 用例 6：业务诊断（异常归因）

### 输入
> 转化率最近两周掉了 0.8 个点。详情页跳出率上来了，购物车没变。详情页改版上周二上的。建议回滚试试。

### 期望输出特征
- 总论点必须包含"根因初步定位 + 优先动作"
- 一级论点结构应近似"现象 / 时间相关性 / 后续动作"
- 改版时间与下行窗口重合的因果关系必须显式写出
- "回滚" 必须落到"小流量 A/B 验证"等可执行表达，不是"建议回滚试试"
- 短判断中不得出现 `0.8`（含小数点 `.`），数据放到正文

## 用例 7：超长输入压力测试

### 输入（约 800 字流水账，混合执行 + 数据 + 客套）
> 各位领导好，本月我们团队整体表现还不错，做了很多事情。GMV 这边大概 2 亿，比上月涨了 8%。订单 100 万，涨了 5%。新客投入了不少，新增 7 万人，但次月留存还需要观察。库存周转有点慢了，大概慢了 4 天。看板这边上线了一个新的经营日报，老板可以每天看。SQL 这边修了一些 bug，主要是 GMV 重复计算的问题，影响了几个看板。私域那块沉淀了 12 万用户，季度目标还差一些。我们觉得整体还可以，但是新客留存和库存这两块需要重点关注。下月计划重点搞下留存和库存。感谢领导支持。

### 期望输出特征
- 输出全文 ≤ 800 字（不含原文回放）
- 一级论点 ≤ 5 条
- 模型必须**主动取舍**，不能把每条原文都翻译成二级
- 优先保留：经营结果数据 / 关键风险 / 下一步动作
- 主动丢弃：客套话（"各位领导好""感谢领导支持"）、口语（"我们觉得""还可以"）、重复表达
- 全部 12 项 checklist 通过

## 用例 8：纯业务诊断无数据

### 输入
> 最近物流投诉变多了，主要是发货慢和错发。准备和供应链对一下。

### 期望输出特征
- 完全没有具体数据，但仍能形成完整三层结构
- 短判断不得是 `物流投诉：` `发货：` `错发：` 等字段名
- 投诉成因（发货慢 / 错发）必须分别成段或并段呈现
- 后续动作"和供应链对一下"必须改写为更具体的"协同范围 / 协同节奏 / 收口时点"
- 数据位全部用 `待补充：XX数据`

## 用例 9：禁止过程性输出（铁律）

### 输入
> 帮我把这段月报改成拉条子。我们这个月主要做了三件事：建了订单宽表、上线了经营看板、还修了 GMV 重复计算的 bug。

### 期望输出特征
- 输出**第一行**为加粗总论点（如 `**...**` 形态），其前不得有任何引导文字
- 全文**不出现**以下任意短语：
  - `现在我来` / `先做抽取` / `原文事实抽取` / `归桶` / `以下是改写结果` / `改写如下`
- 不出现"好的""收到""下面汇报""明白了"等开场
- 不出现"以上即为""整体改写完毕""希望能帮到您"等收口
- 不出现"我先把它分成几个一级"等过程宣告

### 自动判定标准（pass / fail）
- **PASS**：输出文本 grep `'现在我来\|先做抽取\|原文事实抽取\|归桶\|以下是改写结果\|改写如下'` 匹配数 = 0
- **PASS**：输出文本第一非空行以 `**` 开头并以 `**` 结尾（即首行为 `**总论点**`）
- 任一不满足即 **FAIL**

> 由 `scripts/validate_skill.py` 检查 5 强制（每个正例 block 必须 grep 不到上述短语）。

## 用例 10：多工作流月报必须保留 5 条独立一级论点

### 输入
> 这个月做了好多事情。跨平台命令行工具这边 mac 和 windows 双端都搞定了，安装比之前简单多了。Agent 工作台那边接了几个数据源，能跑一些基础查询了，但还在迭代。自助分析站点也上了一个 demo，业务可以自己拖一拖看简单数据。基础经营看板这边迭代了几版，加了几个维度。AI 报告链路这块在探索，用大模型生成月报草稿，但准确性还要再看看。下个月想把 Agent 工作台数据连接做得更完整。

### 期望输出特征
- 一级论点保持 **5 条**（每条对应一个原文工作流，不得压缩为 3 条）
- 工作流顺序保留：跨平台 CLI → Agent 工作台 → 自助分析站点 → 经营看板 → AI 报告
- 不得将 5 条工作流合并为 `工具建设 / 看板迭代 / AI 探索` 这类 3 条粗粒度归类
- 每条一级论点的二级 bullet 同时承载该工作流的"现状判断 + 下月动作"
- 一级论点数 ≤ 6（月报多工作流场景上限）

### 自动判定标准（pass / fail）
- **PASS**：独立成行的非二级 `**...**`（即非二级标题的加粗行）数量 = `1 总论点 + 5 一级` = 6 行
- **PASS**：5 条一级论点中分别出现 5 个工作流关键词：`跨平台命令行工具` / `Agent 工作台` / `自助分析站点` / `基础经营看板` / `AI 报告链路`
- **PASS**：5 条一级出现顺序与原文一致
- 任一不满足即 **FAIL**

> 人工 + 简单 grep 即可检查。validator 不强制工作流顺序但 SKILL 的"工作流完整性"章节明确要求。

## 用例 11：克制型措辞（不超出用户事实）

### 输入
> 跨平台命令行工具这边 mac 和 windows 双端都搞定了，安装比之前简单多了，团队同事也都用上了。

### 期望输出特征
- **不出现**以下放大型词汇：
  - `零门槛` / `大幅` / `完全打通` / `全自动` / `闭环完成` / `显著` / `极大` / `巨大`
- 用克制型替换：`降低使用门槛` / `明显` / `初步打通` / `形成雏形` / `基本跑通`
- 用户原文未出现的绝对化词汇，输出不得引入
- "搞定了"可改写为 `完成打通` 或 `链路打通`，**不得**升级为 `完全贯通` / `零门槛安装`

### 自动判定标准（pass / fail）
- **PASS**：输出文本 grep `'零门槛\|大幅\|完全打通\|全自动\|闭环完成\|显著\|极大\|巨大'` 匹配数 = 0
- 任一命中即 **FAIL**

> 由 `scripts/validate_skill.py` 检查 7 强制（每个正例 block 必须 grep 不到上述放大词）。

## 用例 12：占位符节制（≤ 2 处）

### 输入
> 这个月跨平台命令行工具完成了双端打通，Agent 工作台接了几个数据源，自助分析站点上了 demo，经营看板迭代了几版，AI 报告链路在探索。下月聚焦扩展和迭代。

### 期望输出特征
- 全文 `待补充：` 占位符**不超过 2 处**
- 没有具体数字时，**优先写定性判断**（如 `分析提效初步显现` / `连接覆盖逐步扩展`），不堆叠占位符
- 不为"显得严谨"而在每个段落都加占位符
- 用户未显式要求"数据完整性盘点"时，2 处上限严格生效

### 自动判定标准（pass / fail）
- **PASS**：输出文本 `'待补充：'` 出现次数 ≤ 2
- 出现 3 次或以上即 **FAIL**

> 由 `scripts/validate_skill.py` 检查 6 强制（每个正例 block 不超过 2 次）。

## 用例 13：二级标题判断性（动作 + 结果 + 业务意义）

### 输入
> Qoderwork 那边接了数据，FBI 看板加了维度，ODPS 工具链双端跑通了。

### 期望输出特征
- 所有 `**...：**` 形态的二级标题：
  - 长度 8–18 字
  - 无禁用标点（`,` `.` `;` `，` `。` `；` `、`）
  - 含"动作 + 结果/状态 + 业务意义"
  - **不得**仅写工具名 / 平台名 / 项目代号（如 ❌ `ODPS 工具链：` / ❌ `FBI 看板：` / ❌ `Qoderwork 数据连接：`）
  - 推荐 ✅ `双端安装链路完成打通：` / ✅ `数据连接底座初步建成：` / ✅ `货品诊断视角持续补齐：`
- 判定法：把标题给一个不知道工具名的事业部老板看，他能否一句话理解"做了什么 + 什么状态 + 对业务有何意义"

### 自动判定标准（pass / fail）
- **PASS (a)**：每个 `**...：**` 形态的二级标题都包含至少一个动作 / 趋势 / 状态词（如 `打通` / `建成` / `跑通` / `收敛` / `上线` / `推进` / `修复` / `验证` / `评估` / `迭代` / `消化` / `扩展` / `补齐` / `接入` / `落地` / `治理` / `突破` / `探索` / `形成` / `持续` / `沉淀` / `完成` / `达成` / `达标` / `先行` / `可见` / `可用` / `成为` / `阻力` / `增长` / `下行` / `提升` 等，详见 `scripts/validate_skill.py` 的 `JUDGMENT_WORDS`）。**长度无豁免**——即便标题 ≥ 8 中文字，只要不含任何判断 / 动作词即 FAIL（如 `自助分析平台：` / `经营看板系统：` 这类"形容词 + 容器名"的纯名词短语）。
- **PASS (b)**：标题不以以下后缀结尾（覆盖纯字段名 + 纯容器名两类）：
  - 字段名后缀：`情况` / `数据` / `工作` / `现状` / `概况`
  - 容器名后缀：`平台` / `系统` / `工具链` / `看板` / `工作台`
  - 即便标题别处含判断词，结尾命中容器名后缀也 FAIL（如 `用户增长平台：` 含 `增长` 但仍违反——因为整体形态是"X 平台"）
- **PASS (c)**：标题不得呈现 `[Container][TailVerb]` 形态——即"容器名 + 单个动作动词"在标题末尾紧邻出现，中间没有指代名词 / 范围 / 结果。
  - 容器名：`看板` / `平台` / `系统` / `工具链` / `工作台` / `报告` / `工具` / `站点` / `链路`
  - 尾动词：`迭代` / `上线` / `建成` / `落地` / `打通` / `搭建` / `修复` / `治理` / `推进` / `升级` / `验证` / `探索` / `启动` / `跑通` / `收敛` / `推出` / `接入` / `改造` / `重构` / `搭通`
  - ❌ `经营看板迭代：` (看板 + 迭代) / ❌ `自助分析平台上线：` (平台 + 上线) / ❌ `ODPS 工具链打通：` (工具链 + 打通) / ❌ `Agent 工作台落地：` (工作台 + 落地)
  - ✅ 容器与尾动词之间放入指代名词即可解：`核心经营看板维度持续补齐：` (看板 + **维度** + 持续 + 补齐)
- 任一不满足即 **FAIL**

> 由 `scripts/validate_skill.py` 检查 4 强制：所有文档明确禁止的工具名 / 平台名 / 看板名 / 容器+动词形态标题（`ODPS 工具链：` / `FBI 看板：` / `Qoderwork 数据连接：` / `自助分析平台：` / `经营看板系统：` / `用户增长平台：` / `Agent 工作台：` / `用户增长情况：` / `经营看板迭代：` / `自助分析平台上线：` 等）会被直接 fail。

## 评分建议（人工或自评）

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 短判断合规率 | 出现字段名或含禁用标点 | 多数合规但 1–2 条边界 | 全部合规 |
| 四要素完整 | 缺数据 / 解释 / 判断 | 偶有缺项 | 段段齐备 |
| 数据真实 | 出现虚构数字 | 全部真实但占位过多 | 真实 + 占位合理 |
| 业务价值语言 | 仍是执行语言 | 部分转换 | 全部转换 |
| 语气与冗余 | 出现口语 / 感叹 / 客套 | 偶有 | 干净克制 |
| 长度控制 | > 800 字或层级超限 | 接近上限 | 800 字内且层级合规 |
| 输出形态铁律 | 出现过程性短语 / 客套开场 / 收口语 | 偶有引导句 | 首字符即加粗总论点 |
| 工作流完整性 | 5 条独立工作流压缩为 3 条 | 略有合并 | 4–6 条工作流逐一保留 |
| 措辞克制 | 出现放大型词汇（零门槛 / 大幅 / 完全打通 / 全自动 / 闭环完成） | 偶有 | 全部克制商务化 |
| 占位符节制 | > 2 处 `待补充：` | 接近上限 | ≤ 2 处且每处都是核心指标 |

总分 13 分以上视为"达到拉条子风格"（满分 18，新增 4 项各 2 分）。
